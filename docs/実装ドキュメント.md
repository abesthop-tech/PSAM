# PSAM 実装ドキュメント(AI向け技術資料)

このファイルは、`PSAM CLAUDE CODE用設計書.md`(Obsidian)を元にClaude Codeが実装した内容の記録です。
今後このプロジェクトに手を加える際は、まずこのファイルと設計書を読んでから着手してください。

## 2. 設計書からの逸脱・実装判断

設計書のルール7に基づき、重要な判断は逐次ユーザーに確認しながら進めたが、以下は「大枠から外れない軽微〜中程度の判断」として実装時に決定したもの:

1. **`pools` テーブルを追加**(設計書の3.4に無いテーブル)。
   `pools(key PK, display_name, sort_order)`。プールをハードコードせずUIから新規作成・改名できるようにするため。`items.pool` / `groups.pool` / `pool_config.pool` は文字列でこのテーブルのkeyを参照する(SQLite上は緩いFK)。
2. **composition プールも取り込み対象にした**。設計書3.2のプール一覧(character/expression/clothing/拘束方式/小物/背景/体型)には無いが、`axes/composition/pool.json` が expression/pool.json と同じ「カテゴリ名→単語配列」のワードバンク構造だったため、同じロジックでpart化して取り込んだ。`composition/pools/自作構図.json` はカテゴリ横断のサブセットとして1グループ(`自作構図`)にリンク。BASE_POSTURE起点の条件付き有効/無効という木構造ロジックはDBスキーマの対象外なので実装せず、`_note`のみ`pool_config`に保存(参照はしない)。
3. **LoRA強度のデフォルト値**。元JSON(character/pool.json等)には`lora`(ファイル名)はあるが強度の数値が無いため、移行時に `lora_model_strength = 1.0`(lora_nameがある場合のみ)、`lora_clip_strength = NULL`(modelと同値扱い)を補完した。
4. **画像アップロード機能は実装しなかった**。設計書は「image_path: プレビュー画像の相対パス(なくてもよい)」としており、実データも画像を持たない。Items編集パネルには相対パスを直接入力するテキスト欄のみを用意した(ブラウザのfile inputは実ファイルパスを取得できずダミーになるため、誠実性のため見た目だけの偽アップロードボタンは作らなかった)。
5. **グループ管理画面の「選択を外す」ボタンの意味を明確化**(設計書6章の懸念点)。ボタン文言を「選択したアイテムをグループから削除」に変更し、グループからのリンク解除(アイテム自体は削除されない)であることを明示した。
6. **プロンプト作成画面の右カラムの同期ロジック**は `frontend/src/utils/promptText.ts` に集約。各追加アイテムについて「挿入した正確な文字列断片」を記録しておき、削除時はその断片だけを除去する方式(`appendSegment`/`removeSegment`)。LoRAタグは`<lora:name:...>`を正規表現で検出して置換/削除する(`upsertLoraTag`/`removeLoraTag`)。テキストエリアはユーザーが自由に手動編集できるため、記録した断片が見つからない場合は何もしない(手動編集を壊さない)。
7. **ComfyUI連携**は外部ライブラリを増やさずPython標準の`urllib`でローカルComfyUI APIへ接続する。接続先・既定値・最終送信設定はgit管理外の`backend/local_settings.json`に保存する。
8. **生成履歴はプロセス内のみ**。`comfy.py`の`SESSION_JOBS`に今回のPSAM起動中に送ったジョブID、使用アイテム、送信時刻を保持する。PSAM再起動後の履歴復元は行わない。
9. **LoRA適用は絵柄・キャラクターの2系統**。Build由来アイテム、Positive内のLoRAタグ、置換候補から推測し、ComfyUIのモデル一覧から実相対パスを解決する。ワークフロー生成時はPositive内のLoRAタグを除去する。置換候補にLoRAがある場合は候補ごとのModel/CLIP強度を優先する。
10. **置換生成**は選択文字列の開始・終了位置と候補をブラウザ側で保持する。ランダムは候補直積をシャッフルして先頭N件、網羅は直積全件を送信するため、同一組み合わせの重複は発生しない。

## 3. データベーススキーマ(実装版)

設計書3.4のテーブルはほぼそのまま実装。差分は上記2.の`pools`追加のみ。

- `items`: `UNIQUE(pool, name)`。`type`は`'part'|'finished'`の文字列(CHECK制約はSQLite側では付けていない、アプリ層でのみ検証)。
- `item_variants`: `item_id`外部キー、`ON DELETE CASCADE`。
- `groups`: `parent_group_id`は将来のサブグループ用、現状は常にNULL。
- `item_group_links` / `item_links` / `finished_from_parts`: 複合主キーの中間テーブル。`item_links`は無向グラフとして扱うため、登録時に`(item_id_a, item_id_b) = sorted(a, b)`に正規化している(`routers/items.py`の`add_link`)。
- `aliases`: テーブルのみ用意、現状どの画面からも書き込み/参照していない(設計書通り将来用)。
- `pool_config`: `(pool, key)`はユニーク制約なし(実装は都度`filter_by`で検索→更新 or 新規)。移行スクリプトが書き込むキー例: `pool.json:_note`, `pool.json:_config`, `完成済み表情:_note`, `完成済み表情:_config`。
- `favorite_items`: お気に入りアイテムIDを保持する中間テーブル。
- `prompt_sets`: Positive/Negativeと、使用アイテム・バリエーション・LoRA強度をJSONで保存する。

## 4. 移行スクリプト (`backend/app/migrate/migrate_json.py`)

- 実行: `cd backend && ./venv/Scripts/python.exe -m app.migrate.migrate_json`
- upsert方式(pool+nameで存在チェック)なので何度実行しても重複登録されない。既存itemの`positive/negative/lora/memo`は毎回マスターJSONの内容で上書きされる(= axesのJSONを直接編集してから再実行すれば反映される)。
- プールごとに専用関数(`migrate_character` / `migrate_wordbank_master` / `migrate_expression_finished` / `migrate_composition_subset`)。新しいプールをJSONから追加したい場合はこの4パターンのどれに近いか判断し、専用関数を書き足すか流用すること(データ形状が異なるため汎用化していない)。
- 実行結果は`backend/migration_log.txt`に上書き保存される。`[CONFLICT]`はマスターとサブセットファイルの内容不一致(要人間確認、自動修正しない)、`[WARN]`はサブセット側にのみ存在する語などの軽微な不整合。

## 6. フロントエンド設計メモ

- ルーティング: `react-router-dom`(`/`=プロンプト作成, `/comfy`, `/quick-build`, `/groups`, `/items`, `/database`)
- 状態管理: 外部ライブラリなし。各画面がuseState/useEffectで直接APIを叩く素朴な構成(個人利用規模のため)。
- スタイル: Tailwind v4(`@tailwindcss/vite`)。カラートークンは`src/index.css`の`@theme`でモックアップのダークテーマ(`bg-base #1a1a1a`等)を再現。
- アイコン: 外部CDN(FontAwesome等)は使わず`components/Icons.tsx`に自前SVGを用意(ローカルWebアプリのためオフラインでも動作させたい意図)。
- ComfyUI画面の下書き・生成条件・置換ルールは`localStorage`、Buildからの一回限りの引き渡しは`sessionStorage`を使う。
- ComfyUI画面は固定ヘッダー、スクロール可能な本文、ドラッグで幅変更できる右プレビュー欄からなる。最上位を`w-full min-w-0 overflow-hidden`として余白・横はみ出しを防ぐ。
- `ItemPickerModal`は用途共通の候補選択UI。ComfyUI用途ではカテゴリー、グループ、検索、全選択/解除、候補ごとのLoRA強度と一括強度設定を有効にする。

## 7. 未実装・今後の課題(設計書スコープ外として意図的に見送ったもの)

- `pool_config`の`_config`(word_range, presetなど)を使ったランダム抽選機能(設計書145行目で今回不要と明記)
- `aliases`テーブルを使った日本語⇔danbooruタグの検索連携
- `groups.parent_group_id`を使ったサブグループ階層
- ComfyUI生成履歴の永続化・PSAM再起動後の復元
- 絵柄用・キャラクター用を超える任意個数のLoRA Loader
- ControlNet/IPAdapter等を含む任意ComfyUIワークフローの読み込み
- SQLite→JSON以外の方向(JSON→SQLiteは移行スクリプトのみ、双方向同期はしない)
